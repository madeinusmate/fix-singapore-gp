# Firestore only for published layouts, hosted on Vercel

Drafts stay in the browser. A Google sign-in is required only to publish or upvote, and the published layout is a Firestore document. The leaderboard ranks by a `votes` counter on each layout, kept honest by security rules: a vote is a batch that creates or deletes `layouts/{id}/votes/{uid}` and moves the counter by exactly one. That keeps ranking a single indexed query, so Firestore still fits; Supabase would only win if the homepage had to filter and sort on several computed fields. The site itself is hosted on Vercel. Sign-in uses `signInWithPopup` and the project's `firebaseapp.com` auth domain, because that is the redirect URI Google has registered for the Firebase web client. Pointing `authDomain` at the site hostname makes Google reject the popup with `redirect_uri_mismatch` until `https://<site>/__/auth/handler` is added on that OAuth client. The `/__/auth` rewrite stays in place for that same-origin setup; it is unused while auth stays on `firebaseapp.com`.
